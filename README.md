# 투자 시장 대시보드

국내 투자자 수급, KOSPI·KOSDAQ 비차익 프로그램매매, 미국 유동성 지표를
Streamlit에서 확인하는 읽기 전용 대시보드입니다.

## 운영 구조

- Streamlit은 저장된 JSON 캐시만 읽으며 KIS 토큰을 발급하지 않습니다.
- GitHub Actions가 평일 15:47 KST에 실행되며, 전날 토큰의 실제 만료시각이
  늦어진 경우를 위해 16:47·17:47 KST 보조 실행을 둡니다.
- 모든 배치 실행은 같은 동시성 잠금을 사용하며 KIS가 응답한 실제 만료시각에
  30초 안전 여유를 두고 기존 토큰을 재사용합니다. 정상 실행의 중복 발급을
  줄이지만, 응답 유실·상태 커밋 실패까지 포함해 하루 한 번을 보장하지는 않습니다.
- 토큰은 기존 `KIS_APP_SECRET`에서 파생한 키로 AES-256-GCM 암호화한 뒤
  `data/kis_batch_state.json`에 저장합니다. 앱 시크릿과 평문 토큰은 파일,
  커밋, Streamlit 화면에 저장하지 않습니다.
- 배치는 미국 유동성·비차익 프로그램매매를 먼저 수집하고 상태와 암호화 토큰을
  즉시 커밋한 뒤 수급 스캐너를 별도 단계로 실행합니다. 스캐너가 실패하거나
  제한시간을 넘겨도 앞 단계의 데이터는 보존됩니다.
- 각 API 단계는 같은 토큰으로 최대 3회 재시도하며 60초, 120초 순서의 지수
  백오프를 적용합니다.
- 수급 재시도는 검증된 동일 거래일 차트를 재사용하고 신규·미갱신·무효 종목만
  다시 조회합니다. 수급 350종목이 모두 당일이고 목록만 지연된 경우에는 바로
  부분 완료로 게시한 뒤 다음 예약 실행에서 목록을 재확인합니다.
- KIS 토큰 서버에 연결 자체가 성립하지 않은 `ConnectTimeout`만 5초, 10초 후
  안전하게 재시도합니다. 서버에 요청이 전달됐을 가능성이 있는 다른 오류는
  즉시 다시 요청하지 않고 30분 대기 상태를 저장합니다. 이후 실행에서는
  재요청할 수 있으므로 응답 유실 상황의 중복 발급까지 보장하지는 않습니다.
- 배치 상태에는 목표 거래일, 단계별 성공·실패·대기 상태, 시도 횟수, 실패 사유,
  마지막 갱신시각을 기록합니다. 실패한 토큰 요청은 30분 뒤 다시 시도할 수 있어
  만료 전 요청 실패가 하루 전체를 막지 않습니다.
- `workflow_dispatch` 수동 실행은 장 마감 전이나 주말에도 직전 완료 거래일을
  대상으로 동작하므로 누락된 배치를 즉시 복구할 수 있습니다.
- 거래일은 `exchange_calendars`의 XKRX 달력으로 계산합니다. 휴장일과 지연
  마감을 반영하고 종가 시각 후 15분을 수집 준비 시간으로 둡니다. 현재 검토
  범위는 2026년까지이며, 이후에도 수집은 계속하되 달력 검토 안내와 함께
  매 거래일 16:45 이후 보수적으로 수집합니다. 실제 API 응답 날짜도 검증합니다.
  달력 패키지가 지원하지 않는 범위는 평일로 추정하지 않고 실패 처리합니다.
- 시가총액 목록이 200·150개로 검증되지 않으면 수집을 중단하고 기존 캐시를
  보존합니다. 샘플 두 종목으로 대체하지 않습니다.
- FinanceData의 당일 목록 CSV는 거래소 기준일보다 늦게 게시될 수 있습니다.
  [제공자의 날짜별 원본](https://github.com/FinanceData/fdr_krx_data_cache)을 목표일
  기준 최근 5거래일 안에서 최신순으로 조회하고 코드·이름·시가총액·시장 구분과
  독립적인 200·150종목 규모를 검증합니다. 이전 목록을 사용하면 실제 목록
  기준일을 표시하고 부분 완료로 남겨 다음 배치에서 최신 목록을 다시 조회합니다.
  수급 관측일은 별도로 당일을 검증하며, 5거래일 안에 유효 목록이 없으면 실패
  처리합니다. 이전 목록이 영구 고정되거나 두 종목으로 축소되지 않습니다.
- 수급은 실제 마지막 관측일을 확인합니다. 전 종목 당일 자료가 있어야 완료로
  간주합니다. 최소 5행의 실제 거래일이 중복 없이 증가해야 하며, 목표일 이후
  관측·무한대·비수치·0 이하 가격·필수 수급 필드 누락은 유효 자료로 인정하지
  않습니다. 검증 실패 자료는 매수·매도 신호에서도 제외합니다.
  3회 재시도 후 각 시장의 80% 이상만 확인되면 `degraded` 부분
  캐시를 게시하고 미갱신·누락 종목과 실제 기준일을 표시합니다. 다음 예약과
  수동 실행은 재시도하며, 일부 미갱신을 거래정지로 단정하지 않습니다.
  당일 확인률이 80% 미만이면 기존 캐시를 보존합니다.

## 화면

1. **국내 수급 스캐너**: KOSPI·KOSDAQ 시가총액 상위 200·150종목 외인/기관 5일 수급과 종목 차트 (지수 구성종목과 다름)
2. **비차익 프로그램매매**: KOSPI·KOSDAQ 일별 비차익 순매수와 기간 누적
3. **미국 유동성**: TGA, M2, Overnight Reverse Repo, 지급준비금

미국 지표는 FRED의 원 발표 주기를 유지하고 화면 단위만 십억 달러로 통일합니다.

## 설정

GitHub 저장소의 Actions secret에 다음 두 값이 필요합니다.

- `KIS_APP_KEY`
- `KIS_APP_SECRET`

Streamlit Secrets에는 KIS 키나 GitHub 실행 토큰이 필요하지 않습니다.
`수동 갱신` 버튼은 GitHub Actions 화면을 엽니다. 본인 GitHub 계정으로 로그인한
실행 권한 보유자만 `Run workflow`를 누를 수 있습니다. 공개 방문자는 서버의
권한으로 실행할 수 없습니다. 기존 `GITHUB_ACTIONS_TOKEN` 설정은 사용하지
않으며 Streamlit Secrets에서 제거해도 됩니다. 완전히 완료된 거래일은 버튼을
비활성화하고, 부분 완료는 재실행할 수 있습니다.

Keep Streamlit Awake는 실제 대시보드 제목이 보이고 앱 예외가 없을 때만
성공합니다. HTTP 200, Streamlit 기본 화면, health 응답만으로 성공 처리하지
않습니다. 플랫폼 로그인으로 이동했다면 배포 접근 설정을 확인해야 합니다.

## 로컬 실행과 테스트

```bash
pip install -r requirements.txt
streamlit run app.py
python -m unittest discover -s tests -v
node --test tests/test_streamlit_probe.mjs
```

국내 캐시는 KIS 공식 API, 미국 유동성 캐시는 FRED CSV를 사용합니다. 캐시가
누락되거나 수집 결과가 게시 기준에 못 미치면 기존 정상 캐시를 보존합니다.
테스트 CI는 외부 데이터 수집이나 토큰 발급 없이 검증합니다.

달력 유지보수: 연말에 최신 XKRX 휴장·특별 운영시간 공지를 확인하고
`trading_calendar.py`의 검토 연도와 지연 마감 날짜를 갱신합니다. 2026년 수능
날짜는 [교육부 발표](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=294&boardSeq=100526)를
반영해 16:30 이전 완료로 처리하지 않습니다. 거래소 최종 공지에 변경이 있으면
함께 갱신해야 합니다.
